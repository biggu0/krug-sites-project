# 横版模板与本地/远程存储兼容记录

更新时间：2026-08-28  
适用分支：`cos-template`

## 本次目标

- 支持与现有 12/13/24/25 页产品规则一致的横版 PDF 模板。
- 本地 Vinext/Cloudflare 开发环境可以导入、读取和删除模板。
- 远程部署继续使用已有腾讯 COS 配置，不要求重新配置。

## 遇到的问题与原因

### 横版被显示成竖版

测试文件 `DZKHKGLA413-1002.pdf` 是 13 页横版 A4，页面框为 `841.89 × 595.276 pt`，旋转标记为 0。最初的预览和导出代码把页面固定成竖版 `595.276 × 841.89 pt`，导致内容被纵向拉伸。

修复后使用 PDF 第一页真实页面框识别方向，并将页面宽高用于定制区域坐标、图片初始适配、300 DPI 输出、前景保护层、订单信息页和最终 PDF 导出。

### 模板管理预览仍保持竖版

模板绘制窗口已经正确横向显示，但模板管理预览仍被高优先级 CSS `height:min(62vh,620px)` 固定高度。宽度和高度同时固定时，`aspect-ratio` 不生效。

修复后模板管理预览高度改为自动计算，并按当前 PDF 的宽高比显示；横版双预览默认放大到每张最大约 620px 宽，小窗口自动切成单列。

### 模板预览模糊

旧逻辑只按 PDF.js `0.55` 倍生成 JPEG，再在模板管理或放大窗口中拉伸，文字和细线明显模糊。

修复后背景模板及前景保护层均按 2 倍分辨率生成 PNG 预览。24/25 页模板只渲染实际插图页和必要的第 1 页示例，避免高精度预览无谓占用浏览器内存。该变化只影响网页预览清晰度，最终导出仍直接保留原 PDF 模板页面。

### 本地导入报 COS 配置不完整

`cos-template` 原逻辑默认强制选择 COS，本地没有远程密钥时无法上传。改为：

- 明确设置 `TEMPLATE_STORAGE_PROVIDER` 时优先服从该值；
- 未明确设置但检测到完整 COS 变量时自动使用 `cos`；
- 没有 COS 配置的本地 Worker 开发环境使用 `database` 后备存储。

因此，远程原有 `TEMPLATE_STORAGE_PROVIDER=cos` 和 COS 密钥仍然生效，不需要重新配置。

### 本地数据库读取到 0 字节 PDF

Cloudflare D1/本地 Worker 对直接绑定 `ArrayBuffer` 的返回形式不稳定，导致上传记录存在但读取结果为空。现在数据库后备存储使用 Base64 文本，并兼容读取 `string`、`ArrayBuffer`、`Uint8Array` 和数字数组；文件接口增加 `Content-Length`，空文件会明确提示删除后重新导入。

## 推送前兼容检查

- `cos`：远程已有环境变量时路径不变，仍使用原 COS 对象前缀和权限策略。
- `database`：只作为没有 COS 配置时的开发后备，不会迁移或覆盖远程 COS 文件。
- `local`：显式配置时仍保留 Node/Docker 文件目录模式。
- 竖版模板：真实页面尺寸仍为竖版，原有显示和导出路径不变。
- 横版模板：预览、绘制、图片调整和导出统一使用真实宽高。
- 页面规则：12/13/24/25 页、封面、单双面和奇偶页插图逻辑没有改变。

## 验证方式

每次相关修改后至少执行：

```bash
git diff --check
npm run build
```

发布前还应分别用一份竖版模板和一份横版模板完成：导入、模板绘制、图片调整、前景保护层（如有）及 PDF 导出抽查。
